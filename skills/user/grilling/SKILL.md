---
name: grilling
description: 对方案、计划、设计或决策进行逐题盘问和压力测试。当用户要求盘问、逐个追问、grill、反复质疑、通过连续提问梳理决策，或显式调用本 Skill 时使用。普通的一次性评审、找漏洞、检查计划或直接执行方案不要触发；触发后一次只问一个决策问题，在达成共识前不执行方案。
---

对我提出的这个方案/计划/设计/想法，逐层深入地盘问我，直到我们达成完全共识。
沿着决策树的每一个分支走下去，逐个理清决策之间的依赖关系。
每问一个问题，给出你的推荐答案。

**规则：**
1. **一次只问一个问题**，等我回复后再问下一个。一次抛出多个问题会让我困惑。
2. **能用代码库查到的事实，自己去查**，不要拿来问我。
3. **决策类的问题才问我**——每一个决策都单独提出来，等我的回答。
4. **在我确认我们已达成共识之前，不要执行方案。**
5. 用户说“够了”“先总结”或要求停止时，立即结束盘问，整理已确认决策、未决问题和风险。达成共识只代表盘问结束，不等于授权执行；执行仍需用户明确提出。

**盘问维度（根据实际情况选择相关维度深挖）：**
- 目标与动机：为什么要做这个？不做的代价是什么？有没有更简单的替代方案？
- 范围与边界：什么情况下这个方案不适用？边界条件是什么？
- 依赖与风险：最可能失败的环节是哪个？如果 X 不可用怎么办？
- 实现方案：为什么选 A 而不是 B？有没有考虑过 C？trade-off 是什么？
- 资源与成本：时间、人力、金钱的瓶颈在哪？最低可行版本是什么？
- 验收标准：怎么判断成功了？失败的标准是什么？回滚方案是什么？
